# 构建与品牌约定

> 2026-10-23 起，本仓库的构建产物按**品牌**分目录，品牌能力按编译参数开关。
> 本文是唯一口径，改动构建相关配置前先读这里。

## 0. 仓库定位（2026-10-23 起）

**本仓库只服务 Maadori。**

| 产品 | MFA 来源 |
|---|---|
| Maadori | **本仓库**（`maadori-custom` 分支，含 2603 行定制） |
| MaaEOV | `MaaEOV/vendor/MFAAvalonia`（上游 tag 的独立副本，零共享） |
| Maaon | 待定；若启用同样走各自的 vendor 副本 |

原因：MaaEOV 直接引用本仓库会把 Maadori 的定制带进它的产物，且它的升级流程
（`git checkout <tag>`）会把本仓库的分支状态切走、静默丢掉 Maadori 的功能。
详见 `MaaEOV/docs/MFA源码隔离-20261023.md`。

因此下面 `Brand` 白名单里的 `Maaon` / `MaaEOV` 只是**历史保留**，本仓库不再为它们产出，
也不要把它们的产物从本仓库的 `bin/` 里取。

## 1. Brand 取值

| Brand | 产品 | 产物目录 | 品牌能力 |
|---|---|---|---|
| 不传 / 空 | **兼容模式**（保持引入品牌化之前的行为） | `bin/AnyCPU/Release/` | 全开 |
| `Maadori` | 邦多利国服自动清火打歌助手（**本仓库唯一使用者**） | `bin/Maadori/Release/` | 全开 |
| `Maaon` | BanG Dream! Our Notes 打歌助手（**不在此构建**） | — | — |
| `MaaEOV` | 异象回声自动化（**不在此构建**） | — | — |

**"兼容模式"的准确定义**：不带 `-p:Brand` 的构建 = 当前源码的全部能力，但不注入品牌元数据、exe 图标取 `MFAAvalonia/Assets/logo.ico`。
它不是"纯上游"——定制代码照样编入。真要和上游对照，请 `git checkout` 上游 tag 单独构建。

传了非法值会在**构建开始前硬失败**：

```
error : 未知 Brand 'Bogus'。可选值：Maadori;Maaon;MaaEOV（不传 = 兼容模式）
```

## 2. 构建命令

```bash
# 兼容模式（等价于改造前的构建，老脚本不用改）
dotnet build MFAAvalonia.Desktop/MFAAvalonia.Desktop.csproj -c Release

# 按品牌构建
dotnet build MFAAvalonia.Desktop/MFAAvalonia.Desktop.csproj -c Release -p:Brand=Maadori
dotnet build MFAAvalonia.Desktop/MFAAvalonia.Desktop.csproj -c Release -p:Brand=Maaon
dotnet build MFAAvalonia.Desktop/MFAAvalonia.Desktop.csproj -c Release -p:Brand=MaaEOV
```

同步到运行副本前先关构建服务（否则 `MFAAvalonia.Core.dll` 被锁）：

```bash
dotnet build-server shutdown
```

## 3. 产物目录

| 路径 | 用途 |
|---|---|
| `bin/<Brand>/Release/` | 该品牌的完整产物（Desktop 输出，可直接被各产品的打包脚本取用） |
| `MFAAvalonia/bin/<Brand>/Release/net10.0/` | 类库 `MFAAvalonia.Core.dll` 的品牌输出位置 |
| `MFAAvalonia/obj/<Brand>/` | 品牌中间产物 |
| `bin/AnyCPU/Release/` | 兼容模式产物；**发版不要用它** |

> ⚠️ **类库的 OutputPath 必须一起品牌化。** 否则两个品牌交替构建时写同一份
> `MFAAvalonia/bin/<Configuration>/<TFM>/MFAAvalonia.Core.dll`，
> 只要增量判断有一次认为"输出已是最新"，就会把上一个品牌的程序集复制进另一个品牌的包
> —— 而且文件大小完全一致，肉眼看不出来。

## 4. 品牌能力表

由 `MFAAvalonia/Helper/BrandCapabilities.cs` 在运行时按程序集元数据 `ProductBrand` 判定。

| 能力 | 含义 | Maadori | Maaon | MaaEOV | 兼容模式 |
|---|---|---|---|---|---|
| `QqBotNotify` | QQ 机器人通知渠道 + 设置页卡片 | ✅ | ❌ | ❌ | ✅ |
| `ResultImagePush` | 演出成绩图目录监听与推送 | ✅ | ❌ | ❌ | ✅ |
| `LogImage` | 运行日志渲染成图片 | ✅ | ❌ | ❌ | ✅ |

关闭后的行为：

- 设置页「QQ 机器人」卡片**不可见**（`QQBotCardVisible` 绑定）
- `QQBotEnabled` 即使历史配置里为 true，也被强制置 false
- 发送链路 `case Key.QQBotKey` 有兜底判断，不会推送
- 成绩图监听循环不启动；日志图直接返回 null

**没有用 `#if` 的原因**：需要区分的只有"界面是否出现 + 功能是否生效"，运行期判定就够；
而 `#if` 要动 4 个文件（含无法条件编译的 XAML），维护成本远高于收益。
若将来确实需要"从产物里彻底剔除代码"（减体积、消除休眠代码风险），再引入 `DefineConstants` 开关。

## 5. 品牌资源

| 位置 | 用途 |
|---|---|
| `brands/<Brand>/logo.ico` | exe 图标（`ApplicationIcon` 按 Brand 条件解析） |
| `MFAAvalonia/Assets/logo.ico` | 兼容模式的 exe 图标 + 程序集内嵌窗口图标（兜底） |

**窗口 / 任务栏图标不读 `ApplicationIcon`**，走 `IconHelper.LoadIconWithFallback()`，优先级：

1. `interface.json` 的 `icon` 字段（相对程序根目录）← **各产品换窗口图标的推荐位置，零 C# 改动**
2. 安装目录 `Assets/logo.ico` / `assets/logo.ico`
3. 程序集内嵌 `avares://MFAAvalonia.Core/Assets/logo.ico`

MaaEOV 的 `build_gui_mfa.sh` 用 `-p:ApplicationIcon=` 显式传图标，属于命令行全局属性，优先级高于 `brands/` 约定，不会被覆盖。

## 6. 铁律

1. **发版只用 `bin/<Brand>/Release`。** 用兼容模式目录打 Maadori 的包，等于丢掉品牌元数据与品牌图标。
2. **`AssemblyName` 永远不改。** 源码里 26 处 `avares://MFAAvalonia.Core/...` 硬依赖它，改名必然白屏；产品名只能靠 **exe 改名 + 目录隔离**。
3. **验收用字符串探测，不用 md5。** .NET 编译的 MVID 与时间戳让 md5 每次不同。
4. **探测口径必须区分编码**（详见 `docs/构建基线-20261023.md`）：
   - C# 字符串字面量 → **UTF-16LE**
   - resx 资源文案 → **UTF-8**
   - `AssemblyMetadata` 元数据 → **UTF-8**
   （用 UTF-16LE 去探测元数据会得到"0 命中"的假阴性，2026-10-23 已踩过一次）
5. **不许在 `bin/AnyCPU/Release` 里手动塞定制产物。** 它的语义是"不带品牌参数的默认构建结果"。

## 7. 发版前校验

`Maadori/package_gui.py` 的 `verify_staging()` 已内置品牌校验，打包前会自动拦下：

| 判定 | 触发条件 | 处置 |
|---|---|---|
| 缺品牌元数据 | `MFAAvalonia.Core.dll` 里找不到任何品牌名 | 构建时没传 `-p:Brand=Maadori`，或用了旧的 `bin/AnyCPU/Release` |
| 品牌不符 | 元数据是 `MaaEOV` / `Maaon` | 拿错了构建产物目录 |
| 旧版外壳 | 仍含硬编码 `Maadori通知` | 是品牌化之前的构建，需重建 |

> ⚠️ **2026-10-23 之前构建的外壳全部会被这条规则拦下**（那时还没有品牌元数据）。
> 首次启用新流程时必须先跑一次
> `dotnet build ... -c Release -p:Brand=Maadori`，再 `build_mfa`，再打包。

探测口径：`AssemblyMetadata` 用 **UTF-8**；不要用 UTF-16LE（会得到 0 命中）。

## 8. 机制说明

| 环节 | 位置 |
|---|---|
| Brand 解析、合法值校验、`BrandRoot`、`AssemblyMetadata` 注入 | `Directory.Build.props` |
| `BRAND_<X>` 编译常量 | `Directory.Build.targets` |
| Desktop 输出/中间目录、`ApplicationIcon` | `MFAAvalonia.Desktop/MFAAvalonia.Desktop.csproj` |
| 类库输出/中间目录 | `MFAAvalonia/MFAAvalonia.csproj` |
| 能力表 | `MFAAvalonia/Helper/BrandCapabilities.cs` |

> `BRAND_<X>` 常量**必须**在 `Directory.Build.targets` 里注入：`DefineConstants` 的默认值
> 由 SDK 在项目求值之后写入，在 `.props` 阶段追加会被整体覆盖掉。
